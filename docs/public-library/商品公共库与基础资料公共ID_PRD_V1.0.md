## 1. 项目概述与范围

总部新增独立公共商品库，商品模板引用公共商品。商品、分类、属性分类、属性组、属性值、小料、推荐标签新增对应的公共ID，供总部向门店同步时匹配。普通连锁及品牌总部均适用。单门店沿用原商品表和现有页面，保留各门店自己的本地ID，增加公共ID对应字段及无公共ID保存确认。商家APP、总后台、运营商PC后台执行各自已确认的权限限制；除已明确的保存提示和开放平台总部菜单隐藏外，不增加业务UI改版。属性值公共ID仅数据库保存，所有前端不展示。用户端不新增页面。总部公共库无历史数据，不涉及总部历史资料迁移；门店无公共ID旧资料仍按本期初始化规则处理。

## 数据匹配与改动范围

其他端的属性组、属性值已有本地唯一ID，本次仅总部补齐独立属性组、属性值记录及公共ID；门店原有结构、本地ID和商品关联保留。总部向门店同步均按公共ID匹配。表格导入是例外：分类、属性分类及属性按名称匹配，同名复用；商品仍按商品公共ID处理。快捷导入分类、属性、小料按公共ID复用或新建，不按名称合并。商品只能选择本连锁公共库内有效且有公共ID的资料。五类初始化统一从商品模板管理的【门店商品初始化】进入。

## 2. 业务流程

创建公共分类和小料 → 创建公共属性分类、属性组及属性值、推荐标签 → 新建或导入公共商品 → 模板添加商品 → 选择商品、门店和同步类型 → 核对更新字段 → 点击确定 → 二次提示 → 再次确定提交任务 → 查看目标门店及失败明细 → 对资料未变化的失败项重试。确认门店已同步公共商品、可正常经营后，再按类型清理门店无公共ID旧资料。

## 权限、身份与演示边界

公共ID不跨连锁；提交、执行、重试复核账号与门店范围。原型使用本地内存示例，不连接后台，不修改真实门店，不代表真实数据库唯一性、并发/队列、Excel解析或旧APP验证已完成。刷新重置演示。门店本地ID和公共ID是两套身份。 总部公共ID与门店本地唯一ID分别保存。商品、商品分类、属性分类、属性组、属性值、小料、推荐标签均采用同一规则：总部同步的公共ID用于跨门店识别同一份公共资料；每家门店的本地ID仅标识该门店自己的记录，不要求与总部或其他门店相同，也不由公共ID覆盖。

### 身份清单与关联

| 资料类型 | 公共ID | 关联及更新规则 |
| --- | --- | --- |
| 商品 | 商品公共ID | 模板引用、门店商品映射；更新保留门店本地商品ID |
| 分类 | 每个一级/二级分类公共ID | 子分类记录父级公共ID；改名不换ID |
| 属性分类 | 属性分类公共ID | 属性组记录所属分类ID |
| 属性组 | 属性组公共ID | 类型、选择方式、必选、数量及值集合 |
| 属性值 | 每值独立公共ID | 数据库一行一个值，记录所属组公共ID，可关联小料公共ID；值ID不在前端展示 |
| 小料 | 小料公共ID | 与引用它的属性值公共ID分别保存 |
| 推荐标签 | 标签公共ID | 标签记录不等于商品是否推荐开关 |

公共ID均由系统生成、只读、稳定、不复用；同一连锁内引用，门店同步禁止按名称回退匹配；仅表格导入的分类、属性分类和属性按名称匹配，同名复用对应资料；快捷导入的分类、属性及小料均按公共ID复用或新建，再关联商品。ID示例前缀只是原型显示，不规定生产编码方案。

```text
公共分类和小料 → 公共属性分类、属性组及值 → 推荐标签
                        ↓
手动新建 / 表格导入 / 关联门店快捷导入 → 公共商品
                        ↓
重新创建模板并添加公共商品（引用不复制） → 选商品 / 模板全部 → 选店 → 四种操作
                        ↓
点击确定 → 操作类型二次提示 → 确定提交 → 异步任务 → 门店结果 → 失败项重试
                        ↓
门店具备公共商品与公共基础资料、可正常经营
                        ↓
商品 / 分类 / 属性 / 小料 / 标签初始化分别清理无公共ID旧数据
```

### 总部公共库与门店数据归属

| 范围 | 存储与公共ID规则 |
| --- | --- |
| 总部公共商品库 | 新增独立表，不复用原商品表；公共商品创建成功后生成公共ID |
| 总部公共基础资料 | 公共分类、属性分类/组/值、小料等在公共库创建时生成各自公共ID |
| 单门店商品和资料 | 沿用原商品表及原资料体系，增加各类型公共ID映射字段，本地ID保留 |
| 总部下发到门店 | 例如总部商品公共ID为P100，门店保存的公共ID也为P100；已有门店本地ID保留，新建记录只生成门店本地ID |
| 门店自行新建资料 | 不生成公共ID；支持提示的端先确认再保存，旧版商家APP按原流程保存；均保持公共ID为空，既有权限优先 |

公共ID是总部公共资料的身份标识；门店自建商品、分类、属性、小料及其新建组/值不自动获得公共身份。门店快捷导入形成新的总部资料时，无公共ID的新资料在公共库生成新ID；来源商品有公共ID时不通过快捷导入新建商品：当前连锁公共库存在同ID则跳过、不覆盖，不存在同ID也跳过、不导入；无公共ID商品按原规则生成新公共ID，不回写来源门店。


### 属性现状与本次范围

除连锁店总部外，其他端的属性组、属性值已具有本地唯一ID。本次只在总部将属性组和属性值分别保存，并为其生成公共ID，不新增其他端的文本拆分或结构迁移；其他端原有唯一ID、属性结构和商品关联保留，按既定规则增加或维护公共ID映射。既有本地唯一ID不直接当作总部公共ID。

### 总部公共ID与门店本地唯一ID

总部公共ID与门店本地唯一ID分别保存。商品、商品分类、属性分类、属性组、属性值、小料、推荐标签均采用同一规则：总部同步的公共ID用于跨门店识别同一份公共资料；每家门店的本地ID仅标识该门店自己的记录，不要求与总部或其他门店相同，也不由公共ID覆盖。

| 资料示例 | 总部公共ID | 门店A本地ID | 门店B本地ID |
| --- | --- | --- | --- |
| 商品 | P100 | 501 | 806 |
| 商品分类 | C100 | CA501 | CB806 |
| 属性分类 | AC100 | ACA501 | ACB806 |
| 属性组 | G100 | GA501 | GB806 |
| 属性值 | V100 | VA501 | VB806 |
| 小料 | A100 | AA501 | AB806 |
| 推荐标签 | T100 | TA501 | TB806 |

以上仅为说明ID关系的示例，不要求前端新增ID展示。总部再次同步时，门店A和门店B分别用总部公共ID找到自己的本地记录；已有映射保留本地ID，按既定规则新建缺失资料时生成门店本地ID并保存总部公共ID。商品和资料的层级、关联连接本门店对应记录。门店原有无公共ID资料不因名称相同自动建立公共ID对应关系；本说明不改变两种导入匹配规则、四种同步的新增/跳过范围、推荐标签默认更新规则及各端既定UI范围。

### 套餐组成商品关联

套餐组成商品公共ID：连锁店总部在已有权限允许添加套餐的情况下，选择的商品如带有商品公共ID，保存套餐时必须在套餐内该商品的关联记录中同步保存对应商品公共ID，多个组成商品逐项对应，保留字符串原值及前导零。套餐自身ID、组成商品本地ID与商品公共ID分别保存，不混用；无公共ID商品不自动补发公共ID，套餐操作仍沿用既有权限。该规则不改变模板选品排除套餐分类/套餐商品的范围。


## 3. 功能需求详述

## 公共商品库 · 商品管理

### PUB-ID-001 商品与基础资料使用稳定公共ID

所属端：连锁店总部；需求状态：已明确。

商品身份和关联资料全部由公共ID连接。

**功能规则**

- 左侧菜单：一级菜单为：商品管理；二级依次为：公共商品库（新增）、商品模板管理、商品任务记录、套餐任务记录
- 公共商品库内展示五个页签，按从左到右顺序依次为【商品管理】、【分类管理】、【属性管理】、【小料库管理】、【推荐标签】；进入公共商品库时，默认选中并展示【商品管理】页签。
- 顶部按顺序常驻以下四条说明，切换公共库页签仍可见。
- 顶部说明1：连锁店总部可在公共商品库中创建和管理商品，并将商品同步至门店。系统通过商品公共ID识别对应商品，用于后续商品信息更新。
- 顶部说明2：无商品公共 ID 的商品不可同步到连锁店关联的门店，建议直接删除，并从公共商品库重新添加。删除模板中的旧商品不会删除门店已有商品；
- 顶部说明3：如果门店已经同步了公共库的商品，门店的旧商品可以清除。
- 顶部说明4：总部公共商品资料与导入说明：商品可通过新建、导入表格或关联门店快捷导入添加。总部不维护总库存、每日库存和虚拟销量。请使用最新版导入表格，单次最多 200 条。下载表格示例 ↓
- 点击顶部说明中的“下载表格示例 ↓”直接下载示例表格，不弹窗、不跳转页面；原型沿用现有新版CSV示例。
- 公共库创建的商品、一级/二级分类、属性分类、属性组、属性值、小料、推荐标签均拥有系统生成、只读、稳定且不复用的公共ID；门店自建资料不生成公共ID。
- 同一连锁内，同一个商品、分类、属性分类、属性组、属性值、小料或推荐标签，在总部、引用它的模板及各门店保存相同的公共ID；门店自己的本地ID分别保留。
- 按“所属连锁＋公共ID”识别，名称只用于展示和搜索；同名不同ID不得合并。
- 改名、调价、排序、上下架不改变公共ID。
- 同一门店内，同一类资料的一个公共ID只能对应一条有效记录；
- 数据归属：连锁店总部新增公共商品库使用独立新表，不再复用原商品表；单门店商品仍复用原商品表，原商品及关联资料体系增加商品公共ID、分类公共ID、属性分类公共ID、属性组公共ID、属性值公共ID、小料公共ID、推荐标签公共ID字段；
- 总部同步至门店时，门店保留自身本地ID，并保存与总部一致的公共ID
- 门店无公共ID资料经快捷导入形成总部新公共资料时，仅在总部公共库生成公共ID，不回写来源门店，也不把来源门店原资料改成总部下发资料；表格导入和快捷导入的既定匹配规则继续执行。
- 展示边界：属性值公共ID仅数据库保存，前端不展示；商家端通过公共ID处理数据，UI沿用现有；总后台、运营商PC界面UI本期暂无调整。
- 总部公共ID与门店本地唯一ID分别保存。商品、商品分类、属性分类、属性组、属性值、小料、推荐标签均采用同一规则：总部同步的公共ID用于跨门店识别同一份公共资料；每家门店的本地ID仅标识该门店自己的记录，不要求与总部或其他门店相同，也不由公共ID覆盖。
- 套餐组成商品公共ID：连锁店总部在已有权限允许添加套餐的情况下，选择的商品如带有商品公共ID，保存套餐时必须在套餐内该商品的关联记录中同步保存对应商品公共ID，多个组成商品逐项对应，保留字符串原值及前导零。套餐自身ID、组成商品本地ID与商品公共ID分别保存，不混用；无公共ID商品不自动补发公共ID，套餐操作仍沿用既有权限。该规则不改变模板选品排除套餐分类/套餐商品的范围。

**边界与异常**

- 跨连锁公共ID不能引用；不存在、已删除或已失效的引用在保存和执行时重新校验。

**验收标准**

- 两个同名商品可保留不同ID；改名后同步只按照公共ID查询商品进行更新。
- 门店业务界面不新增ID展示字段。
- 左侧“商品管理”菜单区与顶部菜单导航栏中的“公共商品库”统一标记为①，均关联本条需求说明；点击任一①查看同一条说明，菜单切换功能保留。
- 总部新公共商品与门店原商品分开存储；门店本地ID不变，公共ID仅由公共库创建，门店自建不产生公共ID。
- 同一总部资料同步到多家门店时，各门店公共ID与总部相同，本地唯一ID分别保留；再次同步按公共ID定位，不能直接用另一门店的本地ID匹配。
- 有套餐添加权限的总部选择带公共ID商品并保存套餐后，每个组成商品关联记录都保存各自原商品公共ID；同名不同ID不混淆，前导零保留。无ID商品不自动生成ID，套餐自身ID及商品本地ID不被公共ID覆盖，受限总部不因此获得套餐权限。

### PUB-PROD-001 商品列表与行内编辑

所属端：连锁店总部；需求状态：已明确。

商品列表支持筛选、名称和图片编辑，以及排序、价格、打包费失焦自动保存。

**功能规则**

- 商品名称：名称模糊或者公共ID精准搜索；促销类型：默认全部，可选择：全部、无、折扣、第二份促销；商品分类：默认全部，下拉可选择未删除的全部一级分类。
- 列表展示勾选、商品公共ID、排序、图片及名称、分类、分类类型、促销类型、价格、打包费、启用状态、编辑/复制/删除；名称可换行，最多展示两行，超过两行以省略号展示；
- 复制商品时，仅生成新的商品公共ID；关联的分类、属性、小料和推荐标签沿用原公共ID。
- 商品标题右侧【编辑】打开“编辑商品信息”弹窗，仅展示并允许修改商品名称和商品图片，回显当前名称和图片；图片点击后选择本地文件并预览。底部取消、确定，取消或关闭不保存，确定仅更新当前商品名称和图片。该入口不进入完整商品编辑表单，不展示价格、分类、属性等其他字段；沿用现有名称/图片校验及同步锁，商品公共ID和其他信息保持不变。
- 空列表“暂无数据”，筛选空“暂无符合条件的商品”；状态提示“仅启用的公共商品可同步到门店”。
- 排序、价格、打包费仍在列表中以有边框的输入框展示，可直接编辑，失去焦点后自动保存；启用状态只读。列表最右侧操作列原有【编辑】继续使用完整商品表单，与名称旁名称/图片编辑入口区分。

**边界与异常**

- 当前连锁存在待处理或处理中的同步任务时，商品信息、属性、分类、小料、推荐标签均不可编辑或删除，包含行内保存和批量操作；保存及删除时再次校验，提示“商品正在同步，暂无法编辑/删除”。

**验收标准**

- 筛选只改变显示集合；页面刷新才重置演示数据。
- 编辑保存仅变更总部及模板引用，不自动同步门店。
- 公共库五个页签顶部均展示上述四条说明；点击说明中的“下载表格示例 ↓”直接获得示例表格文件。
- 公共库商品列表，商品名称长名称最多两行，超出省略；名称右侧编辑入口可用。
- 修改排序、价格、打包费后移出焦点，列表对应值自动保存；不改变未编辑商品或门店数据。
- 商品名称旁编辑只打开名称和图片弹窗；取消不保存，确定后仅这两个字段更新，列表及模板回显一致；公共ID及其他字段、未选商品和门店数据保留。

### PUB-PROD-002 创建、编辑与复制公共商品

所属端：连锁店总部；需求状态：已明确。

商品只能使用新版公共基础资料。

**功能规则**

- 创建成功生成商品公共ID；编辑只读显示；复制商品之后，新商品将生成新的公共ID。

### PUB-PROD-003 公共库批量分类、删除与模板移除

所属端：连锁店总部；需求状态：已明确。

公共库删除商品前，校验运营中且未删除的关联门店是否存在同公共ID商品；存在则禁止删除，不存在才可按原确认和同步锁规则删除并移除模板引用。

**功能规则**

- 删除总部公共库商品（单项或批量）前，按当前所属连锁与商品公共ID，校验关联门店中是否存在该商品。校验门店范围仅为运营中且未删除的关联门店；任一家该范围门店存在相同商品公共ID，即不可删除对应公共商品；全部该范围门店均不存在时，才可按既有权限、同步锁及二次确认删除。非运营中、已删除、已解除关联或其他连锁的门店不计入该校验范围；商品名称、门店本地ID不作为匹配依据，商品下架或禁用不等于不存在，公共ID按字符串精确匹配并保留前导零。允许删除时同时从所有引用它的商品模板中移除，不删除门店已有商品。
- 删除入口和最终确认提交时均复核上述门店存在性；不允许通过旧弹窗或批量删除绕过。被拦截时提示“商品在运营中且未删除的关联门店中存在，不可删除”，公共库商品、模板引用及门店数据均不变。模板内移除商品仍仅解除当前模板引用，不套用公共库删除的门店存在性校验。
- 批量修改分类只处理点击入口时本次勾选的商品集合，无选中商品时提示“请先选择商品”；不扩大到未选商品或筛选全部结果。

- 切换一级分类后清空原二级选择；有二级时必须选择二级，不能仅保存一级。底部取消、确认，取消不改商品；确认前复核分类有效性、父子归属、所选商品是否被同步，未通过不提交修改。
- 确认成功后，本次勾选的所有商品统一按新分类展示，商品关联的分类公共ID更新为所选目标分类公共ID；存在二级则写入所选二级分类公共ID，否则写入所选一级分类公共ID。商品自身公共ID不变，未选商品及公共分类定义不变；公共库列表和模板引用展示新分类，不自动更新门店已有商品。
- 模板的删除则仅移除该模板关系，公共库及其他模板、门店不变。

**边界与异常**

- 公共分类/属性/小料/标签被引用时删除，复用现有的删除逻辑；如果有商品使用，不可删除分类、属性、小料；标签可以删除，删除之后同步商品上不显示。

**验收标准**

- 删除前确认范围；公共库与模板的删除提示不同。
- 批量修改先询问再选分类，初始只有一级、有子类才显示二级且切换清空；取消/校验失败不改数据，成功后仅勾选商品的新分类展示与分类公共ID一致。
- 运营中且未删除的关联门店存在同公共ID商品时，公共库单项及批量删除均受保护，入口及确认提交复核；非运营中、已删除、解除关联、其他连锁或仅同名/不同ID不误拦截。无符合范围门店存在时可按原流程确认删除并移除所有模板引用，门店商品不被删除；模板内移除仍按原规则执行。

### PUB-IMPORT-002 关联门店快捷导入

所属端：连锁店总部；需求状态：已明确。

快捷导入时，门店商品有公共ID而当前连锁公共库不存在该ID则跳过；已有同ID商品继续跳过，无公共ID商品按原规则新建；分类、属性、小料的公共ID处理规则保留。

**功能规则**

- 门店与选品：只能从当前连锁关联、账号有管理权限且正常运营、未删除、未禁用的门店导入；展示门店名称，支持下拉选择及按名称模糊搜索，默认显示10家，原ID搜索能力保留。选择一家门店后下方展示该门店可导入菜品，切换门店清空原门店已选商品和分类。
- 商品资料：仅导入商品资料，不导入销量、点赞、门店总库存、每日库存、虚拟销量。来源门店旧商品不会因导入自动获得公共ID。
- 商品公共ID（已存在）：来源商品有公共ID且总部公共库已存在相同公共ID，跳过，不导入、不覆盖已有资料；公共库原ID不变。
- 商品公共ID（不存在）：来源门店商品存在公共ID，但当前导入的连锁店总部公共库不存在相同商品公共ID，该条数据不导入，直接跳过；不保留该ID新建商品、不重新分配商品公共ID，不因该条跳过商品创建分类、属性、小料等关联资料。其余所选商品按各自规则继续处理。商品公共ID按字符串精确匹配，保留前导零，不按商品名称、分类或门店本地ID判断。
- 商品公共ID（未填写）：来源商品无公共ID时，无论公共库是否有同名同分类商品，均按各自来源本地ID逐条导入，每件创建一条独立公共商品，系统逐件生成唯一新公共ID；不按名称或分类合并。
- 分类：保留商品所属一级分类归属；来源有二级分类时，商品归到对应一级分类。公共库缺少所需分类时，随导入创建对应一级分类，不复制二级分类。
- 完整属性：商品分类与商品属性一并处理。新建资料时保留来源完整属性分类、属性组、属性值及结构和选择规则，包括属性/规格/小料类型、单选/多选/必选、选择数量、规格组合、适用价格和小料配置；总部存在相同公共ID的资料时，直接使用总部已有资料，不按来源名称或配置覆盖。
- 基础资料公共ID匹配：分类、属性（含属性分类、属性组和属性值）、小料均按各自公共ID判断。来源资料有公共ID且总部存在相同公共ID时，直接复用总部已有资料；来源无公共ID，或总部不存在该公共ID时，新建总部对应资料。无公共ID的新资料由系统生成公共ID；仅名称相同不能作为复用依据。
- 依赖与创建顺序：先按公共ID复用或新建分类及小料，再复用或新建对应属性资料；新建“小料”类型属性时关联已处理的小料公共ID，最后关联商品。总部存在同ID资料时直接复用其现有内容；同一来源资料在本次导入中被多个商品引用时复用同一处理结果。来源ID不同或均无ID的不同资料，即使同名也分别处理。
- 快捷导入顶部说明：按商品公共 ID 判断是否导入。①门店商品有公共 ID，且公共库已有相同 ID：跳过，不重复导入、不覆盖。②门店商品有公共 ID，但当前连锁公共库没有相同 ID：该条不导入，直接跳过。③门店商品无公共 ID：直接导入，每件生成一个唯一的新公共 ID。门店中同名的不同商品分别导入，不按名称或分类合并。商品分类和完整商品属性一并导入，包括属性组、属性值、规格及小料配置。不导入门店销量、点赞、总库存、每日库存和虚拟销量。分类、属性、小料按公共ID匹配：总部存在相同公共ID直接复用；来源无公共ID或总部不存在该公共ID时新建，再关联属性和商品；不按名称合并。
- 查询范围：套餐分类不在左侧分类展示，套餐分类下的菜品及套餐商品均不查询、不展示、不参与勾选或导入数量统计。
- 独立促销排除：菜品类型标记为【促销】、即参加门店单独促销活动的商品，不查询、不展示、不允许选中导入。此标记不是是否打折；不能仅因商品有折扣或第二份促销配置而排除，未标记独立促销且符合其余条件的商品仍可查询。
- 选品布局沿用现有的：顶部展示现有“快捷导入顶部说明”，其下为门店名称搜索与下拉选择；下方三栏依次为分类、当前分类菜品、已选商品。分类展示已选数及可选总数，支持全选、分类勾选、单品勾选、跨分类保留、单项移除及全部删除。全部计数及全选范围只包含过滤后的可导入商品。
- 无符合条件门店时显示空状态并禁止导入；选店后无可导入菜品时展示空状态，不出现已排除的套餐或独立促销商品。确认导入时再次核对门店资格及已选菜品，已失效的门店或已变为套餐/独立促销的商品不能通过历史勾选继续导入。

**边界与异常**

- 未选商品时提示至少选择一件；只处理当前门店已勾选商品，不扩展到未选商品。
- 总部存在同ID分类、属性或小料时，即使来源名称、配置不同也直接复用总部已有资料；总部不存在同ID资料时新建，不因名称相同复用其他ID记录。
- 提交时重新按当前连锁公共库核对商品公共ID；有公共ID但公共库不存在的商品逐条跳过，不使其他可导入商品整批失败。该商品级规则不改变可导入的无ID商品所需基础资料的公共ID复用/新建规则。

**验收标准**

- 来源商品有公共ID时：当前连锁公共库存在同ID继续跳过、不覆盖；公共库不存在同ID也跳过、不新增商品或该商品依赖资料、不分配新ID，并计入跳过数量。混合选择时其他符合条件商品继续导入；无ID同名同分类商品仍分别新建且ID不同，来源门店不回写。
- 支持有效关联门店名称模糊搜索、下拉选店及原ID搜索；未关联、其他连锁、未正常运营、已删除、已禁用或无管理权限门店均不可选。切换门店清空原勾选，三栏选择、分类计数、全选、取消及已选移除正确。
- 来源二级分类折到对应一级；缺分类时创建一级分类，不复制二级。
- 新建的属性资料保留来源完整分类、组、值、结构、选择数量、规格组合、价格及小料配置；复用资料以总部已有内容为准，不导入门店销量、点赞或各类库存。
- 分类、属性、小料分别验证：总部存在相同公共ID则直接复用总部资料及其配置，不新增或覆盖；总部不存在同ID记录或来源无公共ID则新建，即使与总部资料同名也不合并。同一来源资料在本批次内由多个商品引用时只处理一次，关联关系正确。
- 套餐分类及其菜品、独立促销商品在查询、分类、列表和全选计数中均排除；普通折扣商品不因折扣配置被排除。确认前门店或商品资格改变时阻止失效数据导入。

## 公共分类管理

### PUB-CAT-001 公共分类与层级身份

所属端：连锁店总部；需求状态：已明确。

分类改名与调整按ID更新，不因名称相同合并门店分类；连锁店总部分类管理仅查询和显示含公共ID的数据。

**功能规则**

- 一级、二级分类分别生成公共ID，二级记录父级公共ID；名称/排序变化不改变ID。
- 新商品必须选择新版公共分类，父子关系无效不可保存。
- 同步商品到门店时，先按分类公共 ID 匹配门店分类：不存在则新建，已存在则更新分类信息，并保持与总部一致的父子分类关系；完成后，将商品关联到对应分类。
- 门店已有的无公共ID分类独立保留，不因名称相同与公共分类合并。
- 分类页沿用原有添加、编辑和删除入口，分类公共ID只读，父子关系保留，不展示门店初始化入口；初始化统一从商品模板管理进入。
- 批量删除入口：分类管理【添加分类】右侧增加【批量删除】；列表增加分类勾选框及全选框，展示已选分类数量。仅删除当前明确勾选的分类，不扩展到未选分类或自动级联删除子分类。
- 批量删除交互：未选分类时提示“请选择需要删除的分类”；已选择时二次确认，展示本次所选分类数量，并说明被使用的分类不删除，其余可删除分类将删除。取消不修改数据；确认后逐项判断，仅删除可删除的总部公共分类，刷新列表并清空勾选，不删除门店已有分类；结果反馈已删除和因被使用未删除的分类数量。
- 批量删除保护：所选分类被商品或子分类引用时，该分类不删除；其他未被使用、符合删除条件的所选分类继续删除，不因某个分类被使用而整批阻断。存在待处理/处理中的同步任务时，仍禁止批量删除；确认提交时重新校验同步任务、分类有效性及引用关系，按提交时引用状态逐项判断，不能删除已被使用的分类。不自动解绑商品、不级联删除子分类。
- 分类列表展示沿用本次原有样式参考图，仅将原“ID”列标题改为“分类公共ID”。列从左至右为勾选框、分类公共ID、分类名称、分类类型、分类图标、显示、排序、操作；不改为名称/信息的简化列表。保留分类名称及排序输入框、分类图标、显示开关、父子分类层级展开与收起、行内编辑/删除操作；顶部保留【添加分类】及右侧【批量删除】。名称、排序和显示状态的修改保留分类公共ID，并受既有同步锁保护。
- 新增分类弹窗沿用本次现有界面样式，标题为“新增分类”。首字段展示只读【公共ID】，新建保存后由系统生成；后续字段依次为分类名称、上级分类、分类类型（普通类型/必点类型）、分类图标、描述、排序、是否显示（开启/隐藏），底部保留取消、确认。分类名称必填，上级分类可选择一级公共分类或无（一级分类）；新建普通类型、开启为默认演示值，实际默认设置沿用现有系统。取消不保存；确认保存分类资料及公共ID，编辑沿用同样式并保留已有公共ID，受现有同步锁保护。
- 单项删除：点击某个分类的删除入口，如果分类被商品引用，保留该分类，提示“分类正在被使用，不可删除”；未被使用且符合删除条件时正常删除。已有子分类引用保护和同步锁继续执行。
- 分类同步时，总部一级/二级分类公共ID与门店本地分类ID分别保存。门店按分类公共ID匹配，已有记录更新且保留本地分类ID；按既定规则新建时生成门店本地ID并保存总部分类公共ID。父子分类及商品关联连接门店对应分类记录，不要求各门店本地分类ID一致。
- 查询范围（仅连锁店总部）：总部公共商品库【分类管理】只查询并显示含公共ID的数据；公共ID为NULL、缺失、空字符串或纯空白的记录不返回、不展示。首次加载、刷新/切换回页面及现有查询/重置均保持此条件；列表数量和可勾选范围与过滤结果一致，不能因名称相同查出无ID资料。公共ID按原值处理，保留前导零；已有无公共ID资料不因不展示而被删除、补发公共ID或迁移，门店旧数据继续按既定规则处理。 本条不适用于单门店的分类、小料、推荐标签列表，单门店仍按原有规则查询和展示，不套用含公共ID的过滤条件。

**边界与异常**

- 共享分类改名可能影响门店其他关联商品展示；共享资料影响按本节规则说明，不额外设置同步预览步骤。
- 分类删除的引用保护已明确：批量删除逐项跳过被使用分类，其余可删除项继续删除；单项被商品引用时提示“分类正在被使用，不可删除”。子分类引用保护沿用，不自动迁移、解绑或级联删除。

**验收标准**

- 同名不同ID分类不合并；改名同步后门店本地分类ID保持不变。
- 批量删除紧邻添加分类右侧；单选、全选/取消全选及已选数量一致，空选提示、确认和取消正确。
- 混选被使用和无引用分类时，仅删除可删除的所选分类；全部被使用时均保留，全部可删除时全部删除；未选分类、商品、门店分类和其他资料不变。单项商品引用提示精确为“分类正在被使用，不可删除”；确认前新增引用按最新状态跳过该项，同步任务仍阻断整个删除操作。
- 同时存在带公共ID和无公共ID的分类时，本页仅返回并展示有ID记录；搜索（如本页已有）、重置和再次进入不带出无ID记录。过滤后无记录时显示既有空态；列表计数及可选择范围一致，带前导零ID保留，过滤不改写或删除原始资料。 同时核对该条件仅作用于总部公共库三个列表；单门店列表查询展示及已有无公共ID资料不受本条影响。

## 公共属性与属性值

### PUB-ATTR-001 总部属性组、属性值独立保存与公共ID

所属端：连锁店总部；需求状态：已明确。

总部的属性分类、属性组和每个属性值分别保存并生成公共ID；其他端保留原有本地ID、结构和商品关联。

**功能规则**

- 属性分类、属性组、每个属性值分别拥有独立公共ID；一个值一行，记录所属组ID，禁止只用逗号文本作为值身份。
- 组类型属性/规格/小料，选择方式、必选、数量范围及排序沿用现有规则；属性值改名/调价保留原ID，新增值生成新ID。
- 删除再建同名值必须生成新ID，不复用被删除的ID。
- 现状与改动范围：除连锁店总部尚未处理外，其他端的属性组、属性值已存在唯一ID，不新增其他端的属性文本拆分或结构迁移任务。总部补齐属性组、属性值的独立记录及公共ID；门店同步在既有组/值结构上按公共ID匹配，保留原有本地唯一ID与商品关联。
- 保留门店本地组/值记录ID；同名不同ID不得更新、串绑；门店缺公共组/值先创建再绑定商品。
- 维护顺序：先创建属性分类，再进入该分类的【属性列表】添加属性，最后在属性内添加属性值；属性必须关联已创建且有效的公共属性分类，不允许跳过分类独立创建。
- 属性分类界面沿用本次现有样式：顶部保留【添加属性分类】，列表列为公共ID、分类名称、属性数、状态、操作；原“编号”改为“公共ID”。操作保留属性列表、编辑、删除，不恢复之前已移除的分类示例按钮或额外标题。
- 分类内属性列表沿用现有样式：顶部【添加属性】、【返回属性分类列表】，展示当前所属分类及属性名称查询；原“编号”改为“公共ID”。列表保留属性名称、属性值名称、属性类型、排序、编辑和删除；每个属性值独立行展示名称，不展示属性值公共ID；属性组公共ID继续展示，属性值公共ID仅在数据库中保存，用于同步匹配与更新。属性名称、排序沿用列表输入方式，修改保留公共ID并受同步锁保护。
- 新增/编辑属性沿用现有弹窗结构：展示当前所属分类和只读公共ID，维护属性类型（属性/规格/小料）、名称、选择规则、数量、排序及值列表；属性与规格类型在弹窗内添加对应属性值，保存后为新增组和值分别生成公共ID，编辑保留已有ID。
- 小料类型必须通过【添加小料】打开小料库选择弹窗，展示名称、公共ID和价格，可搜索、勾选、取消及确认。仅当前连锁总部小料库中含非空公共ID的小料可选，无公共ID的历史小料不展示为可添加项；无可选项时提示先在小料库创建含公共ID的小料。不能通过手填名称创建小料引用。
- 确认小料选择后，将所选小料加入属性值列表；每个值记录独立属性值公共ID及引用的小料公共ID。未新增勾选不重复添加同一小料，保留已有值ID；取消选择不改变原属性草稿。小料确认和属性保存时复核小料存在且有有效公共ID，失效或无ID时阻止保存。保存期间沿用同步锁保护。
- 属性值公共ID不在前端列表、详情、编辑弹窗、商品属性选择器或门店界面展示，不增加只读输入框；属性/规格/小料类型均适用。隐藏展示不影响后台生成、保存、稳定性及按ID更新。
- 属性分类、属性组、属性值逐层保存两套ID：总部公共ID，以及门店各自独有的本地唯一ID。总部下发公共ID，门店按公共ID找到对应的本地分类/组/值；找到则保留本地ID更新，缺失且按既定规则需要创建时，在门店生成本地唯一ID并记录总部公共ID。组所属分类、值所属组及商品关联均连接该门店对应记录；不能用总部公共ID替换门店本地ID，不能拿其他门店的本地ID匹配。

**边界与异常**

- 总部公共商品库为本次新增，初始无历史数据，不涉及总部旧文本属性迁移、旧资料合并或历史关联迁移；新建属性时，组和值分别保存并生成公共ID。
- 删除属性及属性值沿用现有引用校验：仍被商品使用时不可删除。允许删除后，不自动修改门店资料；历史订单按成交时快照展示，不能因删除或改名改变订单内容。

**验收标准**

- 同组两个值各有不同ID；值改名同步后门店相应值的本地ID与公共ID不变。
- 旧版APP编辑不会删除未传回的公共值。
- 可完成新建属性分类 → 进入分类属性列表 → 添加属性 → 添加属性值 → 保存流程，组和值生成不同且稳定的公共ID；返回分类列表后属性数正确。
- 小料弹窗仅显示含公共ID的小料，搜索和勾选可用；取消不改草稿，重复选择不重复添加，已有值保留ID；无ID或已失效小料在选择和保存时被阻断。
- 属性分类和属性组仍按既定规则展示公共ID；各类属性值前端无公共ID列或编号，新增、改名/调价后后台值ID仍按既定规则生成或保留。
- 仅总部将属性组和值分别保存并生成公共ID；其他端原有唯一ID、属性结构及商品关联不因本次调整丢失或被重新编号。
- 属性分类、组、值在两家门店可有不同本地ID但相同总部公共ID；更新不换本地ID或公共ID，门店内部层级及商品引用指向对应本地记录。

## 公共小料库

### PUB-ADDON-001 公共小料按ID同步

所属端：连锁店总部；需求状态：已明确。

公共小料身份与商品的小料属性关联分开；连锁店总部小料库管理仅查询和显示含公共ID的数据。

**功能规则**

- 公共小料独立ID；小料类型的属性值同时保留自身属性值ID与引用的小料公共ID，不把两者混为一个ID。
- 总部小料改名或改价后，总部属性及模板立即展示新值；门店在执行商品同步后更新。
- 门店无同公共ID小料时先创建，名称及价格来自总部，库存默认不限制；门店已有同公共ID小料时复用并更新总部名称及价格，保留门店本地ID与现有库存。小料价格不受商品“价格信息/促销信息”可选开关控制。
- 同名但不同ID或无ID门店小料不直接复用；商品删/下架不级联删/下架小料和属性。
- 小料库沿用现有样式：保留顶部小料说明、小料名称搜索、重置/查询、新增小料；表格增加【公共ID】，其余保留小料名称、价格（元）、关联商品数量、操作（编辑、删除、查看关联商品）。初始化统一从商品模板管理进入，不在小料页展示入口。
- 属性类型为小料时，从当前总部小料库选择，仅含公共ID的小料可添加；无公共ID的历史小料不可选择或保存为新版公共属性的小料引用。
- 新增/编辑小料沿用现有弹窗，首字段为只读公共ID；新增显示“保存后自动生成”，总部公共库保存成功后生成，编辑保留原ID。保留小料名称（最多10字）、价格、取消/确定；取消不保存。
- 总部新增小料有公共ID；单门店自行新增小料无公共ID，保存前执行PUB-STORE-001的确认流程，确认后仍无公共ID。
- 具有公共ID的小料价格统一由连锁店总部维护，同步至门店后门店不允许修改该小料价格，保存时同样校验；门店小料库存仍按既有权限维护。本次不增加门店业务UI改版。旧数据不含公共ID，不按名称与公共小料合并，不新增旧小料价格冲突迁移流程。
- 小料类型属性中的名称和价格以其关联的小料库记录为准，不另存一套可独立修改的价格；总部改名或改价后，总部属性及模板立即展示新值，门店在执行同步后更新。
- 查询范围（仅连锁店总部）：总部公共商品库【小料库管理】只查询并显示含公共ID的数据；公共ID为NULL、缺失、空字符串或纯空白的记录不返回、不展示。首次加载、刷新/切换回页面及现有查询/重置均保持此条件；列表数量和可勾选范围与过滤结果一致，不能因名称相同查出无ID资料。公共ID按原值处理，保留前导零；已有无公共ID资料不因不展示而被删除、补发公共ID或迁移，门店旧数据继续按既定规则处理。 本条不适用于单门店的分类、小料、推荐标签列表，单门店仍按原有规则查询和展示，不套用含公共ID的过滤条件。

**边界与异常**

- 旧小料公共ID为空，与总部公共小料保持独立；本次不将旧数据按同名匹配或覆盖价格。

**验收标准**

- 商品引用的小料值可以追溯至小料ID；同名旧小料保持独立。
- 小料名称查询、重置、关联商品数量及查看关联商品可用；总部新建生成公共ID，编辑/改价后ID不变，取消不新增。
- 新增/更新按小料公共ID处理，价格均与总部一致，保留已有门店本地ID及库存；商品价格开关未勾选时仍同步公共小料价格；门店不得修改已同步公共小料价格，无公共ID旧小料不受影响。
- 同时存在带公共ID和无公共ID的小料时，本页仅返回并展示有ID记录；搜索（如本页已有）、重置和再次进入不带出无ID记录。过滤后无记录时显示既有空态；列表计数及可选择范围一致，带前导零ID保留，过滤不改写或删除原始资料。 同时核对该条件仅作用于总部公共库三个列表；单门店列表查询展示及已有无公共ID资料不受本条影响。

## 公共推荐标签

### PUB-TAG-001 公共推荐标签与推荐状态

所属端：连锁店总部；需求状态：已明确。

推荐标签沿用现有列表及新增、关联商品、删除样式，增加公共ID；连锁店总部推荐标签管理仅查询和显示含公共ID的数据。

**功能规则**

- 推荐标签具有独立公共ID；新商品只选新版公共推荐标签；门店缺少同公共ID标签时先创建，已有同公共ID标签时更新名称等资料。
- 名称变化保持ID；同名无公共ID旧标签不合并。
- 更新商品信息默认保留门店“是否推荐”，与是否推荐字段不同。
- 推荐标签页不展示门店初始化入口；从商品模板的【门店商品初始化】选择“推荐标签”，按标签公共ID为空识别旧数据。
- 列表沿用现有推荐标签样式，顶部保留【＋新增】，增加【公共ID】列；其后为推荐标签名称、关联商品数、创建时间、操作。操作保留【关联商品】【编辑】【删除】，不增加内容区重复标题。
- 新增/编辑推荐标签弹窗首字段为只读公共ID；新增保存成功由系统生成，编辑显示原ID且改名不换ID。推荐标签名称必填、最多3个字，展示字数计数及“最多3个字”；底部为取消、确定，取消不写入。
- 关联商品弹窗标题为“关联商品 - {标签名}”，沿用左侧商品分类（不含套餐）、中间商品列表、右侧已选商品三栏；支持名称模糊搜索、本组全选、勾选及移除，展示商品图片、名称和价格。打开回显当前标签已关联商品，切换分类和搜索保留选择；取消不修改，确定后保存总部公共商品关联并更新列表关联商品数。
- 删除标签前显示确认弹窗：“删除【{标签名}】后，已关联的{N}个商品的推荐标签将被清空，是否确认删除？”；N为总部当前关联商品数，底部取消、删除。确认后删除总部标签记录及总部商品对该标签的关联，不删除商品；其他标签关联保留，不直接删除或修改门店资料及是否推荐开关。
- 推荐标签同步同样区分总部标签公共ID与门店本地标签ID：按公共ID识别标签，保留已有门店本地ID；缺失时按既定规则新建门店标签本地ID并保存总部公共ID。各门店本地ID无需相同；商品推荐标签绑定属于默认更新字段，按公共ID映射到门店对应标签；门店“是否推荐”仍保留原值。
- 更新商品信息时默认按总部商品当前推荐标签覆盖目标商品的标签绑定，无需额外勾选；先按公共ID创建缺失标签或更新同ID标签，再关联该门店对应记录，保留已有标签本地ID。同名不同公共ID标签不合并，不修改其他商品的标签绑定。

- 查询范围（仅连锁店总部）：总部公共商品库【推荐标签管理】只查询并显示含公共ID的数据；公共ID为NULL、缺失、空字符串或纯空白的记录不返回、不展示。首次加载、刷新/切换回页面及现有查询/重置均保持此条件；列表数量和可勾选范围与过滤结果一致，不能因名称相同查出无ID资料。公共ID按原值处理，保留前导零；已有无公共ID资料不因不展示而被删除、补发公共ID或迁移，门店旧数据继续按既定规则处理。 本条不适用于单门店的分类、小料、推荐标签列表，单门店仍按原有规则查询和展示，不套用含公共ID的过滤条件。

**边界与异常**

- 总部商品未关联推荐标签时，更新后清空目标商品的推荐标签绑定；不删除门店标签记录，不修改“是否推荐”开关。

**验收标准**

- 更新标签名称不切换商品推荐开关；不同ID同名标签不会合并。
- 列表及表单显示只读公共ID，新建生成、编辑保留；名称最多3字；关联商品取消不生效、确认后数量正确；删除取消不变、确认清除该总部标签关联且门店数据保留。

- 总部可按既有规则维护推荐标签；关联品牌类型连锁店的门店在商家APP仅查看关联商品，标签维护及绑定变更不写入；普通连锁门店不新增本限制。
- 同时存在带公共ID和无公共ID的推荐标签时，本页仅返回并展示有ID记录；搜索（如本页已有）、重置和再次进入不带出无ID记录。过滤后无记录时显示既有空态；列表计数及可选择范围一致，带前导零ID保留，过滤不改写或删除原始资料。 同时核对该条件仅作用于总部公共库三个列表；单门店列表查询展示及已有无公共ID资料不受本条影响。

## 商品模板与四种同步

### PUB-SYNC-001 四种商品同步

所属端：连锁店总部；需求状态：已明确。

新增、删除、下架、更新都按公共ID匹配。

**功能规则**

- 顺序：新增门店商品、删除门店商品、下架门店商品、更新商品信息；删除【替换门店商品】类型以及同步不按名称匹配。
- 新增：同ID有效商品已存在则跳过；无同ID则新建，同名不同ID不拦截、不删除旧品。
- 删除：仅删同ID商品，目标缺失跳过，不删分类/属性/小料。
- 下架：仅下架同ID商品，已下架为成功无变化，目标缺失跳过，不改依赖状态。
- 更新：仅更新同ID已有商品，保留本地商品ID和销售连续性；缺同ID跳过，不新增、不初始化、不改用名称匹配。
- 普通连锁逐门店选择，品牌按现有区域选择；每次确认展开为当时有效有权限门店集合。
- 上述新增、删除、下架、更新中的“同ID”均指同一连锁内相同商品公共ID，不是门店本地商品ID。门店商品保留自己的本地ID；新增记录按门店现有机制生成本地ID并保存总部公共ID；其余操作在门店按公共ID找到目标后执行，不改变原有跳过/失败口径。
- 同步设置弹窗底部按钮为取消、确定，不提供“下一步”。点击确定先校验商品与门店选择，再弹出当前同步类型的二次提示；二次提示取消返回设置并保留商品、门店及勾选项，点击确定才提交任务，不能在第一次确定时提交。
- 提示中的门店数、商品数使用当前确认范围；可选同步未勾选时显示“未选择”，勾选一项显示该项，勾选两项显示“促销信息/售卖时间”。二次提示为文案确认，不另设范围/依赖预览步骤或列表。
- 门店资格在展示、确认提交、实际执行和失败重试时均校验：必须属于当前连锁有效关联范围、账号有管理权限、正常运营、未删除且未禁用；区域选店只包含提交时确认的门店，之后新增门店不自动加入。执行时不符合条件的门店项失败，其他合格门店继续。

- 任务待处理/同步中不可编辑、删除或变更商品启用状态；任务执行失败并结束后可按原权限修改商品，修改后重新执行旧任务时阻断并提示“商品信息已变更，请重新同步”，需要按当前资料重新发起同步。
- 门店活动限制沿用系统，参与活动不可操作则单项失败，其他商品继续。

**验收标准**

- 四种操作对同名不同ID目标不串改；更新缺失跳过。

### PUB-SYNC-002 更新字段分组与库存保护

### PUB-SYNC-003 先同步关联资料，再同步商品

所属端：连锁店总部；需求状态：已明确。

商品写入前先处理带公共ID的基础资料。

**功能规则**

- 处理顺序：先处理父级和子级公共分类、引用的小料，再处理属性分类、属性组及属性值、推荐标签，最后建立商品关联；各类资料分别按公共ID匹配。
- 同ID更新保留门店本地ID；缺同ID创建；重复ID、失效父级、跨连锁引用阻断商品执行。
- 共享资料影响：多个商品可能引用同一分类、属性组、小料或标签。同步更新这些同公共ID资料的名称、价格或选择规则时，引用它的其他门店商品也会使用更新后的资料；不主动改变其他商品的分类、属性组或标签绑定。
- 总部商品引用的公共资料不存在或已失效时，该商品同步失败，记录资料类型及公共ID；不能改为按名称查找门店资料。
- 分类、属性分类/组/值、小料、推荐标签处理完成后，将总部公共ID对应到当前门店的本地记录，再使用当前门店对应记录维护商品及层级关联；各门店独立维护映射，禁止跨门店混用本地ID。已有无公共ID资料不因名称相同自动与总部资料建立映射。
- 总部删除未同步的影响范围：总部删除商品、分类、属性分类、属性组、属性值、小料或推荐标签后，未执行同步的情况下，不影响门店现有数据；门店已有商品、基础资料及其关联保持不变，不自动删除门店记录或解除门店关联。总部自身删除仍遵守已明确的引用校验及同步锁。

**边界与异常**

- 同步只创建缺失的公共资料、更新同ID资料及所选商品关联，不自动删除门店共享资料。总部已移除的组/值或标签记录，不因本次同步被物理删除；同ID属性组的值按ID新增或更新，未包含的门店原值保留，不把“总部没有该值”当作删除命令。商品的分类、属性组及推荐标签绑定按总部当前配置更新；未选商品的绑定保持原样。
- 单个商品及其关联资料作为一次完整操作提交；任何一步失败，该商品本次修改全部不生效，其他商品继续处理。

**验收标准**

- 同ID基础资料改名后多个商品仍引用同一ID；不同ID同名资料保留。
- 总部完成允许的删除但未执行同步时，门店原商品、分类、属性分类/组/值、小料、推荐标签及原有关联不受影响。
- 同步所选商品不删除门店原有共享资料；分类、属性组及标签绑定按总部更新，其他商品绑定保留；同ID共享资料内容更新可影响其他引用商品，不能承诺其他商品展示完全不变。

## 任务记录与失败重试

### PUB-TASK-001 任务三级结果与字段快照

更新前的旧任务不再展示；更新后初始为空，仅展示更新后新创建的任务，支持任务→全部目标门店→失败商品。

**功能规则**

### PUB-TASK-002 失败重试与同步锁

所属端：连锁店总部；需求状态：已明确。

同步期间锁定商品及相关公共资料；失败重试前核对商品、关联资料和关联关系是否变化。

**功能规则**

- 同步锁：当前连锁存在待处理或处理中的同步任务时，商品信息、分类、属性（含属性分类、属性组及属性值）、小料、推荐标签均不可编辑或删除；包含列表行内编辑、弹窗保存、批量修改、删除及商品启用/禁用状态变更。操作入口及最终保存/删除时均重新校验，不允许通过已打开的编辑界面绕过限制。
- 推荐标签的编辑、删除及商品关联变更，与商品、分类、属性、小料使用相同的同步锁；入口和提交时均校验。
- 失败重试校验：从任务、门店或商品任一入口重新执行失败任务前，比较任务提交时的商品信息与当前商品信息，并比较商品关联的分类、属性（含属性分类、组、值及配置）、小料、推荐标签资料和关联关系。任一内容变更或被删除时，阻止旧任务重新执行，统一提示：“商品信息已变更，请重新同步”。
- 重新提交：资料变化后需按当前资料重新发起同步任务，不得静默替换失败任务中的商品及关联资料；被阻止的重试不增加执行次数，也不写入门店。
- 旧任务重试不能覆盖同门店同公共ID较新已完成任务；连续点击/网络重发与写成功回执丢失不重复新增。
- 重试只保留原任务失败范围和原勾选字段，记录每次尝试时间、失败原因和结果；待处理/处理中不得重复执行，任务结束且无其他同步任务时可重新编辑资料。

**边界与异常**

- 商品名称未变但关联分类、属性或小料内容已变，同样阻止失败任务重试，并使用“商品信息已变更，请重新同步”的提示。
- 仅与原任务商品无关联的公共资料变化，不视为原任务商品发生变化。关联推荐标签变更同样适用失败重试校验。

**验收标准**

- 当前连锁有待处理或处理中的同步任务时，商品、分类、属性分类/组/值、小料、推荐标签的编辑、删除、行内保存和关联变更均受保护；任务结束且无其他进行中任务时解除锁定。
- 分别修改商品信息、关联分类、关联属性及属性值、关联小料或关联关系后，从任务/门店/商品重试入口均阻止执行，提示“商品信息已变更，请重新同步”，执行次数及门店数据不变。
- 原任务资料未变时仅重试失败项，成功项不重复写入；无关资料变化不误判为商品资料变更。
- 同步中商品启用/禁用状态同样不可变更；失败任务结束后修改名称、价格或启用状态，再从任务/门店/商品入口重新执行，均提示“商品信息已变更，请重新同步”，不执行旧任务、不增加尝试次数。

## 门店初始化

### PUB-INIT-001 统一门店初始化入口与类型

所属端：连锁店总部；需求状态：已明确。

门店初始化必须先完成商品初始化；所选门店任一家未完成时，分类、属性、小料初始化提示并阻止继续。统一入口默认商品，五类清理范围保留。

**功能规则**

- 统一入口：仅在商品模板管理保留【门店商品初始化】；
- 初始化类型：点击【门店商品初始化】后，在弹窗中增加单选下拉框“初始化类型”；每次打开默认选中“商品”，选项依次为商品、商品分类、商品属性、小料、推荐标签。仅清理本次所选类型，不同时清理其他类型。
- 普通/品牌沿用选店方式；确认展开门店集合，仅有效运营且有权限门店，排除删除/禁用门店，区域后续新增店不纳入。
- 只处理所选类型公共ID为空的门店旧记录；有公共ID的全部保留，无论是否同名。
- 确认流程：选定初始化类型及门店后，底部按钮为【取消】【确认】；分类、属性、小料先核对所选门店商品初始化完成状态，未通过则按强制前置规则阻断。校验通过及其他类型点击【确认】仅打开二次提示，不创建任务、不删除数据；商品类型提示：“确定删除这 N 个门店中所有没有商品公共 ID 的商品？请确认所选门店已同步带公共 ID 的商品，并可正常经营。”N为本次所选门店数。二次提示点击【确定】后才提交初始化任务并执行；点击【取消】返回原设置并保留类型及选店。
- 商品初始化无可清理商品时，门店结果记为失败，原因“该门店商品均含公共ID”。
- 每类初始化独立提交，不把商品/属性/小料一键混删。
- 未选择门店点击【确认】时提示“请选择初始化门店。”，不打开二次提示、不提交任务。其他初始化类型沿用按所选资料类型的二次确认文案，同样不增加预检步骤。
- 初始化顺序为强制前置：必须先完成门店商品初始化、清理无公共ID旧商品，才允许初始化分类、属性、小料。选择商品分类、商品属性或小料并点击【确认】时，按本次所选门店分别核对商品初始化完成状态；任一门店尚未完成，则分类/属性提示：“门店商品还未初始化，直接初始化分类/属性，可能商品将无法正常使用”；小料提示：“门店商品还未初始化，直接初始化小料，可能商品将无法正常使用”。此时禁止继续，不展示【确定】或其他执行入口，仅可【返回】原设置并保留类型及选店；不创建任务、不清理数据、不自动执行商品初始化。全部所选门店完成后才进入原二次确认；最终提交、执行及失败重试均复核此前置条件，未通过不执行分类、属性、小料清理。不新增预检或候选范围步骤。商品及推荐标签不受本条前置限制。
- 商品初始化完成状态按门店记录成功执行结果判断，不能把已提交、待处理、处理中、失败或部分失败当作完成。同一任务某门店完成而其他门店失败时分别判断；失败项重试完成后可更新该门店完成状态。

**边界与异常**

- 先同步公共基础资料并建立商品关联，再清理门店无公共ID的旧资料；清理只依据公共ID是否为空，不按名称判断。
- 商品分类、商品属性、小料、推荐标签初始化无可清理记录时，该门店记为跳过，原因“无可清理数据”；商品初始化仍使用上述失败规则。

**验收标准**

- 分类、属性、小料及推荐标签页无初始化入口；商品模板内统一入口可打开弹窗，默认商品，五种类型的名称、顺序及切换正确。
- 分类、属性、小料通过商品初始化完成校验后，五种类型均按“确认 → 二次提示 → 确定执行”处理，不展示预检入口或候选表；商品提示按指定原文显示实际门店数，首次确认及取消不提交任务，最终确定才执行。
- 四类基础资料无可清理记录时为跳过，原因“无可清理数据”；商品无可清理记录时为失败，原因“该门店商品均含公共ID”。
- 未初始化、待处理、处理中、失败或部分失败门店执行分类/属性/小料初始化时显示对应类型提示原文；混选中任一门店未完成则整次操作阻断，不出现继续或确定入口。返回保留类型及选店，不创建任务、不清理数据；全部所选门店已完成后可按原二次确认提交。直接调用提交、执行及失败重试仍须校验，前置不满足不可绕过；引用保护及原清理规则保留。

### PUB-INIT-002 引用保护、执行快照与重试

所属端：连锁店总部；需求状态：已明确。

**功能规则**

**验收标准**

- 执行前补上ID的候选被保留。

## 开放平台处理

### PUB-OPEN-001 开放平台绑定连锁品牌后的商品管理处理

所属端：连锁店总部；需求状态：已明确。

连锁总部关联开放平台时只隐藏商品管理及其子菜单，保留其余五项菜单；单门店及未关联的总部保留商品管理。

**功能规则**

- 触发条件：当前连锁店关联开放平台（应用绑定该连锁品牌）且当前身份为连锁总部时，隐藏商品管理。切换单门店或当前连锁未关联开放平台时，保留商品管理菜单，具体操作仍按原有权限执行。
- 左侧菜单按参考图从上到下依次为：首页、商品管理、营销管理、订单管理、门店管理、权限管理。关联开放平台的连锁总部仅隐藏一级【商品管理】及其全部二级菜单，包括公共商品库、商品模板管理、商品任务记录、套餐任务记录等商品管理入口；首页、营销管理、订单管理、门店管理、权限管理的名称、顺序及原有入口均保留。
- 总部商品管理的顶部导航、已有打开页面及直接地址入口不能绕过限制；进入页面或提交相关编辑、删除等商品管理操作时，均按当前品牌绑定关系校验并阻止受限操作。不可仅隐藏菜单而继续允许操作。
- 切换到单门店身份后，保留单门店现有商品操作；不能将总部因应用绑定品牌而产生的整组菜单隐藏规则直接套用至单门店。单门店继续执行其自身既有角色、开放平台及品牌门店权限，不额外放开受限权限。
- 总部与单门店切换时重新判断当前身份和应用/品牌绑定关系，避免沿用上一身份的菜单及操作权限；切换不修改已有商品或门店数据。
- 本次补充为开放平台绑定场景的总部商品菜单显隐和操作限制；其他商家端、总后台、运营商PC业务UI沿用此前确定范围。评审中的绑定/身份选择与权限核对只是场景演示，不新增业务配置入口。
- 未关联开放平台的连锁总部显示参考图全部六项一级菜单，商品管理位于首页下方、营销管理上方；单门店同样保留商品管理菜单，不因所属连锁已关联开放平台而隐藏该菜单。商品管理之外的菜单不受本条关联规则影响，仍沿用原权限。
- 首页改版引导同步按菜单权限过滤：开放平台应用绑定当前品牌的连锁总部，登录首页不展示公共商品库三步引导及手动重看入口。只有具备商品管理菜单权限的总部才可展示，不能通过引导开放被隐藏菜单；未展示不写已读，其他有权限场景继续遵守跳过/确认后不再自动显示规则。评审辅助可从当前绑定场景查看对应总部登录首页，不新增业务配置入口。

**边界与异常**

- 品牌绑定以实际应用关联的连锁品牌为准，不因其他品牌已绑定而影响当前总部。
- 单门店“保留操作”指沿用原权限，不能覆盖已有开放平台创建门店限制或品牌门店多端限制。

**验收标准**

- 关联开放平台的连锁总部依次显示首页、营销管理、订单管理、门店管理、权限管理，不显示商品管理及其子菜单；原有直接访问和提交限制保留。
- 同一关联场景切换至单门店时，显示首页、商品管理、营销管理、订单管理、门店管理、权限管理；切回总部重新隐藏商品管理。未关联开放平台的总部按参考图显示全部六项，保留原商品管理子菜单及权限。
- 场景切换及被拒绝的操作不修改总部公共库、商品、门店或任务数据。
- 已绑定品牌的总部进入首页不出现引导或查看说明入口，未绑定且有商品管理菜单权限的总部首次进入可展示；无菜单权限的账号不弹，首次/已读判断均不能绕过菜单权限。

### PUB-STORE-001 门店公共ID映射与无ID保存确认

所属端：商家APP；需求状态：已明确。

门店沿用现有业务UI和原商品表，数据通过公共ID匹配处理；本条仅规定数据及保存规则，不新增核对页面。

**功能规则**

- 已由总部公共库同步且带有公共ID的门店资料，在允许编辑范围内保存时保留公共ID及关联身份；不因客户端未传公共ID而清空，不弹出无公共ID提示。
- 品牌门店及各端原有权限优先；受限操作仍按既定权限提示阻断，不能通过无公共ID确认继续保存。保存确认不解除同步锁和其他既有保存校验。
- 商家端、总后台、运营商PC沿用现有业务页面、布局和操作表单，不因公共ID数据处理新增界面字段或页面。旧版商家APP无公共ID资料按原流程保存且公共ID保持为空，其他端及支持确认的APP版本沿用既定保存提示；关联品牌类型连锁店的门店，商家APP推荐标签仅可查看，由总部维护。评审权限及兼容结果不是正式UI改版要求。
- 总部公共ID与门店本地唯一ID分别保存。商品、商品分类、属性分类、属性组、属性值、小料、推荐标签均采用同一规则：总部同步的公共ID用于跨门店识别同一份公共资料；每家门店的本地ID仅标识该门店自己的记录，不要求与总部或其他门店相同，也不由公共ID覆盖。 对已建立公共ID映射的记录同步时保留门店本地ID；按既定规则创建缺失记录时，生成该门店本地ID并保存来源总部公共ID。门店自建资料仍只有本地ID、公共ID为空，不因名称相同自动建立公共ID对应关系。

**边界与异常**

- 门店主体沿用现有页面，公共ID只在数据库及数据处理层新增，不在业务界面展示；此前确认的保存提示保留；不新增门店核对页面。
- 旧版商家APP允许保存的无公共ID资料按原有流程保存，公共ID仍为空；已有公共ID的资料保留原值。品牌连锁关联门店的推荐标签只读及其他品牌门店、同步锁等权限限制优先，不因兼容保存而解除。

**验收标准**

- 支持确认提示的端，四类门店资料无ID保存前显示指定确认，取消不写入、确认后仍无ID；旧版商家APP按原流程保存允许编辑的无ID资料，公共ID仍为空。两种情况均不修改总部公共库。
- 已有公共ID记录允许保存后保留原ID；品牌受限操作在确认前或提交复核时阻断，不能经确认保存绕过。

## 首页 · 商品管理改版引导

### PUB-GUIDE-001 首页三步菜单改版引导

所属端：连锁店总部；需求状态：已明确。

新增功能及改版说明仍在总部首页弹窗中展示；仅有商品管理菜单权限时首次自动弹出三步引导，跳过或我知道了后不再自动显示。

**功能规则**

- 触发位置及前提：本次功能更新后，用户首次登录进入连锁店总部【首页】，先按当前账号、当前连锁品牌及开放平台应用绑定关系判断商品管理菜单权限。只有具备商品管理菜单权限才可自动展示三步改版引导；适用于有权限的普通连锁及品牌总部。
- 分步引导：遮罩直接覆盖现有连锁店总部首页，默认展开左侧【商品管理】菜单，第1步虚线标出【公共商品库】，说明新增内容及通过【新建商品】或【导入商品】创建公共商品；【下一步】到第2步，将虚线移至【商品模板管理】，说明旧模板已清空、不再展示，重新创建模板并从公共商品库选择商品，最后同步门店；再次【下一步】到第3步，虚线移至【商品任务记录】，说明旧记录不再展示、仅可查看更新后新记录，无新任务时列表为空。每次只突出当前菜单，支持【上一步】，底层始终为同一首页。
- 展示频次：本次改版更新后，同一用户首次进入对应连锁总部首页展示。每一步均提供【跳过说明】，点击后立即关闭并记录已读；第3步点击【我知道了】也关闭并记录已读。跳过或完成后，再次进入首页、刷新或重新登录不再自动显示本次引导。仅点击【下一步】或【上一步】不写已读，中途离开或刷新且未跳过/未完成，下次进入仍可展示。按用户、连锁总部和本次改版独立记录，不跨用户或连锁共用已读；不提供手动查看或重看入口。
- 新版使用顺序：先在公共商品库创建公共商品，再创建商品模板并添加公共商品，最后同步至门店。更新前的模板数据不自动展示或恢复为新版模板；新版模板依旧引用公共商品，不在模板内直接新建商品。
- 权限优先：开放平台应用已绑定当前品牌的连锁店总部，登录首页不显示本次引导弹窗；其他无商品管理菜单权限的总部同样不显示。未展示不等于已读，不因无权限自动标记为跳过或完成；账号/连锁身份变化后按当前权限重新判断，已读频次规则继续独立生效。

**边界与异常**



**验收标准**

- 有商品管理菜单权限的总部首次进入首页自动开启第1步，三步下一步/上一步仅移动左侧对应菜单的虚线高亮并更新说明，不将底图切为其他业务页面。 首页与商品管理的菜单级别、左侧起始位置及一级样式一致；二级菜单在商品管理下缩进展示。新增说明只在首页弹窗中展示。
- 每一步均可【跳过说明】，立即结束并记已读，之后普通进入和刷新不再自动显示；第3步点击【我知道了】同样结束并记已读。仅下一步/上一步或中途刷新不写已读。不同用户/连锁独立；不提供业务手动查看入口。
- 首页无手动查看说明卡片或按钮，跳过或我知道了后只保留现有首页；
- 开放平台应用绑定当前品牌的连锁总部登录首页不显示引导，且无商品管理菜单；其他无菜单权限同样不弹。权限恢复且未读时可按首次规则展示，已跳过/完成后仍不重弹。窄屏下文案完整、按钮可达。

**本期UI范围**：商家端的数据通过公共ID处理，页面UI无改动；总后台、运营商PC界面UI暂无调整。公共ID映射字段仅在数据库及数据处理层维护，不要求业务界面展示。评审中的权限对照/兼容结果为辅助视图，不是新增业务页面。支持提示的端沿用无ID保存确认，旧版APP按原流程保存；既有权限及品牌连锁关联门店的推荐标签只读规则优先。属性值ID在总部列表、编辑弹窗、选择器及所有门店前端均不展示；属性分类、属性组等其他公共ID的总部展示沿用已确认规则。

开放平台关联场景：参考图左侧菜单依次为首页、商品管理、营销管理、订单管理、门店管理、权限管理。关联开放平台的连锁总部仅隐藏商品管理及全部子菜单，保留其他五项菜单；总部原商品管理的顶部入口和已有页面不能绕过限制。单门店及未关联开放平台的总部均显示全部六项菜单，商品管理入口保留，具体操作沿用原权限。此项为本次明确的菜单显隐调整，其他三端UI范围不扩展。

推荐标签沿用现有列表、新增/编辑、三栏关联商品及删除确认样式。列表首列增加公共ID，其后保留推荐标签名称、关联商品数、创建时间及关联商品/编辑/删除；表单首字段只读公共ID，标签名称必填且最多3字。关联商品排除套餐，取消不保存；删除确认后清除总部该标签关联，不删除商品、不直接修改门店。更新商品信息默认按总部商品的推荐标签覆盖门店商品标签绑定；总部未绑定时清空目标绑定，门店“是否推荐”开关保留，标签按公共ID映射至门店本地记录。

批量修改分类沿用现有两步弹窗：先提示“确定要批量修改这些商品的分类吗?”，确定后展示批量修改分类；默认仅一级分类，选择一级且有二级时才显示必填二级，切换一级清空二级。确认后所选商品统一更新分类公共ID及分类展示，不改变商品公共ID，不自动更新门店。

商品名称旁【编辑】沿用现有“编辑商品信息”弹窗，仅含商品名称、商品图片（本地选择及预览）和取消/确定；不进入完整商品编辑。确定仅保存名称和图片，不更改商品公共ID、分类、价格、属性等其他字段；最右侧操作列的原有编辑表单保留。

**公共库列表查询范围（仅连锁店总部）**：总部公共库分类管理、小料库管理、推荐标签管理均只查询和显示含公共ID的数据。公共ID为NULL、缺失、空字符串或纯空白的记录不返回；首次加载、已有搜索/重置、刷新/切换保持同一范围，数量及可勾选范围一致。不为上述页面新增搜索控件，不删除或补发原始无ID资料的公共ID；本条不适用于单门店列表，单门店的分类、小料、推荐标签仍沿用原有查询展示规则，不套用该过滤条件。
## 5. 操作流程

0. 更新后首次登录进入总部首页，先判断商品管理菜单权限；开放平台应用绑定当前品牌的总部及其他无权限账号不显示引导，且不写已读。有权限时，在现有首页直接叠加遮罩，三步依次虚线高亮公共商品库→商品模板管理→商品任务记录，说明新增商品库及新建/导入、旧模板不展示及从商品库选品、旧记录不展示且仅看新记录。底图始终为首页，不切换业务页面；任一步跳过说明或第3步我知道了均结束并记已读，不再自动显示。无业务手动查看入口；上/下一步不写已读。
1. 在公共分类、属性、小料及标签中创建公共资料；分类、属性组及每个属性值均有公共ID；属性值ID只保存在数据库，其他公共ID按既定规则只读展示。属性先创建属性分类，再进入分类添加属性及属性值；小料类型只能从总部小料库选择含公共ID的小料。
2. 创建公共商品，只从新版公共选择器选择资料；或按表格导入规则，以分类名称、属性分类名称及属性名称匹配并复用同名公共资料；导入新建资料时先生成公共ID再绑定。
3. 公共商品创建后重新创建商品模板，更新前的模板数据不再展示。新增模板保持现有逻辑即可，保存后在模板列表点击【管理商品】进入当前模板商品管理，再点击添加商品，顶部按名称或公共ID筛选，左侧选择分类、右侧勾选商品，分类结果不分页，点击名称只切换展示、一级复选框联选全部下属二级及可选商品，跨分类和搜索保留选择；套餐分类/套餐商品与促销标记商品排除；仅当前模板已添加商品标识且不可选，其他模板添加状态不影响当前模板。确认按当前模板公共ID去重；模板不单独改名改价。
4. 选中商品或同步所有，选择门店和新增/删除/下架/更新，核对字段与范围，点击确定后展示对应同步类型的二次提示，再次确定才提交。
5. 本次更新后任务记录不再显示旧数据，没有新任务时列表为空；新创建任务成功提交后，在任务记录查看该任务全部门店、失败资料与原因，商品及其关联分类、属性、小料、标签均未变化，且未被更新任务覆盖，才重试原失败项；任一变更时提示“商品信息已变更，请重新同步”。
6. 确认门店公共商品可经营后，从商品模板管理【门店商品初始化】第一步选择商品初始化，再执行分类、属性、小料初始化；五类选项保留。所选门店有尚未完成商品初始化时，分类/属性/小料初始化提示“门店商品还未初始化，直接初始化分类/属性，可能商品将无法正常使用”（小料提示为“门店商品还未初始化，直接初始化小料，可能商品将无法正常使用”），禁止继续、不创建任务或清理数据，仅可返回并保留设置；全部所选门店完成后才进入原二次确认；点击【确认】后直接弹出二次提示，商品类型提示“确定删除这 N 个门店中所有没有商品公共 ID 的商品？请确认所选门店已同步带公共 ID 的商品，并可正常经营。”；二次【确定】才执行，取消不提交。不展示预检清理范围或候选列表；按本章门店无公共ID数据清理范围处理，不增加总部历史数据迁移流程。
7. 旧版APP按原流程保存允许编辑的无ID资料，公共ID仍为空；已有ID资料保留原ID及未上传结构。品牌连锁关联门店的推荐标签由总部维护，商家仅查看关联商品。核对新旧版本读取、保存、权限及历史订单展示。


单门店支持确认提示的端允许新增/编辑时：按原表单校验及权限校验 → 判断是否已有公共ID → 无公共ID显示“当前信息保存暂无公共ID信息，后续同步门店无法同步，确定保存么？” → 确定才保存且公共ID仍为空，取消不提交；已有公共ID的记录保存保留原ID。旧版商家APP按原流程保存允许编辑的无ID资料，不要求新增确认交互；公共ID仍为空。品牌连锁关联门店的商家APP标签只读、其他品牌门店限制及同步锁不因兼容保存或确认而解除。


快捷导入逐条先判断商品公共ID：来源有公共ID而当前连锁公共库没有同ID，该条不导入、跳过；已有同ID继续跳过，不覆盖；无ID按原规则新建。公共库删除单项/批量商品时，先核对运营中且未删除的关联门店是否存在同公共ID商品，存在禁止删除，不存在才进入原删除流程，最终提交再次复核；模板内移除商品沿用原规则。
## 6. 边界与异常处理

| 编号 | 场景 | 处理 |
| --- | --- | --- |
| B01 | 门店同步时同名不同公共ID | 独立资料，不合并、不删除、不按名称更新；表格导入分类、属性分类及属性按名称匹配是单独规则 |
| B02 | 同门店同类型重复公共ID | 该项失败，禁止任选一条 |
| B03 | 已删除/跨连锁/失效公共引用 | 保存、执行前阻断并提示资料ID |
| B04 | 表格缺必填 | 整批失败；未知/重复ID仅相应行失败；保留前导零 |
| B05 | 快捷导入分类/属性/小料 | 总部存在相同公共ID则直接复用总部资料；来源无公共ID或总部不存在同ID资料时新建，不按名称合并；先处理依赖再关联商品 |
| B06 | 更新目标缺同商品公共ID | 跳过，不新增、不初始化 |
| B07 | 公共资料被多个商品共享 | 同ID共享资料更新可影响其他引用商品；只改所选商品绑定，不自动删除共享资料，不增加预览步骤 |
| B08 | 门店活动限制 | 该商品失败，其他可处理项继续 |
| B09 | 存在同步中任务时编辑/删除资料 | 商品信息、分类、属性分类/组/值、小料、推荐标签均禁止编辑及删除；入口及提交再次校验，原值保留 |
| B10 | 失败重试时商品或关联资料变化 | 校验商品及关联分类、属性分类/组/值、小料、推荐标签和关联关系；变化时阻止重试，提示“商品信息已变更，请重新同步” |
| B11 | 新增总部公共库历史数据 | 公共库无历史数据，不新增旧资料合并、关联迁移或强制解绑流程；门店初始化按既定范围保留 |
| B12 | 带ID组含无ID值 | 值单独列候选；引用保护；不得漏清理或误删公共子值 |
| B13 | 初始化期间新增无ID资料 | 不在原候选集合，原任务重试不扩大范围 |
| B14 | 执行前候选已补ID / 已删 | 补ID跳过保留；已删为成功无变化 |
| B15 | 门店全部商品有公共ID | 商品初始化记失败“该门店商品均含公共ID” |
| B16 | 旧版APP不回传公共身份字段 | 无公共ID仍为空；已有公共ID及本地ID保留，缺字段或传空均不能清空；未上传结构保留，无法唯一对应属性值时禁止该项结构写入；品牌连锁关联门店标签只读权限优先 |
| B17 | 历史订单引用旧值 | 保留成交快照，不因初始化或改名改写历史成交信息 |
| B18 | 总部分类删除 | 批量逐项跳过被使用分类，其余可删除项继续删除；单项被商品引用提示“分类正在被使用，不可删除”；同步中仍禁止删除 |


品牌类型且非开放平台创建门店按各端限制执行，受限保存不修改数据；连锁类型、开放平台创建门店及未列明操作沿用既有权限。旧版兼容不能绕过权限限制。

快捷导入仅可选择当前连锁有效关联、有权限且正常运营、未删除未禁用的门店。套餐分类及对应菜品不查询；菜品类型标记“促销”的门店独立促销商品不查询，该标记与是否折扣分开判断。列表、全选及计数均使用同一过滤范围，提交再次校验。

无公共ID保存确认：新建和已有无ID记录均需确认；取消不写入。已有公共ID资料不能因保存丢失身份；公共库与单门店数据分开。门店本地ID不可当作公共ID；受限权限不能由确认框绕过。

开放平台应用绑定品牌的总部限制与单门店权限分开判断：总部菜单隐藏不能被直接地址或提交绕过；切换单门店不新增禁用、不放开原有受限权限。身份切换重新校验绑定关系，不修改商品数据。

商品分类、商品属性、小料或推荐标签初始化无可清理记录时，门店结果为跳过，原因“无可清理数据”。仍被使用的旧资料不强制解绑或删除；按项记录失败，其余项继续。

## 7. 已确认规则汇总

以下规则已确认，前文各功能条目为完整说明。

| 范围 | 已确认规则 |
| --- | --- |
| 表格导入 | 分类、属性分类和属性按名称匹配；商品按商品公共ID新增或更新。重复非空ID、未知ID均列出全部相关行号并使对应行失败，不设网页预览。 |
| 快捷导入 | 分类、属性、小料按公共ID判断；总部有同ID则复用总部资料，无ID或无同ID则新建。先处理分类和小料，再处理属性及商品；不回写来源门店。商品已有公共ID时，无论总部有无同ID均跳过；总部无同ID时不导入该条商品及其依赖，其他可导入商品继续处理。无公共ID商品沿用逐件新建规则。 |
| 总部删除与门店影响 | 总部删除公共商品前校验运营中且未删除的关联门店，同公共ID商品存在则禁止删除，全部不存在才可按原流程删除及移除模板引用，单项/批量和最终提交均校验；不直接删除门店数据；删除商品同步只删除同ID门店商品，不级联删除分类、属性、小料或标签。基础资料同步不自动下发物理删除。 |
| 属性及共享资料 | 总部分类、属性、小料被使用时不能删除；标签可删除并解除总部关联。同步更新当前公共资料，按ID新增或更新属性值，原有未包含值保留；所选商品分类、属性组及标签绑定按总部更新，未选商品绑定保留。同ID共享资料的名称、价格或选择规则变化可影响其他引用商品。 |
| 属性记录与展示 | 仅总部补齐独立属性组及属性值记录；其他端保留既有本地ID和结构。每个属性值有公共ID，但所有前端均不展示属性值ID。 |
| 公共小料价格 | 新增及更新均采用总部小料价格，不受商品价格信息勾选控制；保留门店本地ID及库存。同步后的公共小料不允许门店改价。 |
| 推荐标签 | 默认更新标签绑定，无需勾选；总部无标签时清空目标绑定，保留门店“是否推荐”开关和其他商品绑定，不删除门店标签记录。 |
| 同步锁与重试 | 待处理或处理中锁定商品、分类、属性、小料、推荐标签的编辑、删除及关联变更。任务结束后恢复原权限；原任务商品或关联资料变化时，三个重试入口统一提示“商品信息已变更，请重新同步”，不执行旧任务。 |
| 门店初始化 | 先完成商品初始化；未完成的门店执行分类/属性/小料初始化时提示“门店商品还未初始化，直接初始化分类/属性，可能商品将无法正常使用”（小料提示为“门店商品还未初始化，直接初始化小料，可能商品将无法正常使用”），禁止继续；任一所选门店未完成则整次阻断，仅可返回，全部所选门店完成后才进入原二次确认，最终提交、执行及重试复核前置；模板统一入口，默认商品，可选分类、属性、小料、推荐标签；确认→二次提示→确定执行，无预检步骤。商品无候选记失败“该门店商品均含公共ID”；其他类型无候选记跳过“无可清理数据”。有公共ID全部保留，仍被使用的旧资料不强制删除，重试不扩大候选范围。 |

### 旧版商家APP保存与推荐标签权限

| 场景 | 处理规则 |
| --- | --- |
| 允许保存的资料无公共ID | 按旧版原流程保存，公共ID仍为空，不自动生成或按名称补ID；其他既有权限继续执行。 |
| 已有公共ID的商品和资料 | 保留原公共ID及本地ID；旧版未传、传空或改传均不能清空或改写，未上传的结构及关联不变。 |
| 旧版不支持新版属性结构 | 对应结构只读并提示升级；普通允许字段仍可保存，不重建或清空原属性。 |
| 品牌连锁关联门店的商家APP推荐标签 | 新旧版均不能新增、编辑、删除或变更商品绑定，只可查看关联商品；统一由连锁店总部维护。商品保存保留原标签数据，无ID保存兼容不授予标签维护权限。 |

## 三端门店操作权限对照

适用于品牌类型连锁店关联、非通过开放平台创建的门店；连锁类型门店沿用原有角色权限，开放平台创建门店沿用现有开放平台限制。

| 操作 | 商家APP | 运营商PC后台 | 总后台 |
