# 审核中骑手修改小镇归属

版本：V1.0

## 公共说明

创建／修改：2026-11-20；适用端：总后台、用户端、骑手 APP、运营商 PC、运营商 APP；

需求背景：待审核骑手也需要调整小镇归属，并避免运营商或骑手在归属已变更后继续按旧归属操作。

本次改动：

* 总后台对用户端申请、骑手 APP 已实名认证的待审核骑手提供【分配小镇】；APP 未提交资质的申请支持直接注销，注销后可重新申请。
* 按申请来源同步归属，用户端同步显示新小镇及客服电话；审核通过后使用新归属。
* 运营商 PC／APP 审核增加归属校验；骑手 APP 注销保持现有逻辑，仅提示；总后台注销账号后，APP 原界面后续操作提示登录过期。

列表展示：总后台骑手申请／骑手管理、运营商 PC／APP 骑手列表中的骑手手机号暂不脱敏，完整展示手机号。

来源说明：本需求中的“骑手 APP 注册来源”包括“骑手APP注册”和“骑手APP支付宝绑定”，两种来源处理一致。

## 总后台

### 后端调整

#### 待审核骑手分配小镇

所属端：总后台；页面：骑手申请

用户端申请或骑手 APP 已实名认证的待审核骑手可修改归属。

**处理规则**

- 待审核骑手中，来源为“用户端申请”，或属于骑手 APP 注册来源/骑手APP支付宝绑定来源且已完成实名认证的骑手，允许修改小镇归属；操作权限沿用现有规则，可选择全部小镇；只有二次确认后才修改归属，取消不修改。修改成功后，“申请小镇”更新，状态仍为待审核。
- 来源为“用户端申请”：同步调整该骑手申请的归属；用户端待审核详情中的“申请入职的小镇”及下方“小镇客服电话”均更新为新小镇对应信息。
- 骑手 APP 注册来源：同步调整该骑手在申请中的小镇归属；审核通过时，使用修改后的归属，不恢复为原申请小镇。
- 各申请来源的骑手审核通过后，正式骑手归属均以修改后的新小镇为准。


#### 未提交资质的 APP 申请注销

所属端：总后台；页面：骑手申请

总后台确认注销未提交资质的 APP 申请账号，允许重新申请。

**处理规则**

- 待审核骑手属于骑手 APP 注册来源/骑手APP支付宝绑定来源且未提交资质信息时，总后台【骑手申请】列表可注销该骑手账号；二次确认后才执行注销，取消不注销。
- 注销成功后，该账号不可登录骑手APP，本次申请结束；已登录骑手的后续操作按骑手 APP「账号状态与注销校验」处理。骑手可以使用原手机号重新申请，不因原账号已申请而被拦截。



### 前端 UI 调整

#### 待审核骑手分配小镇

所属端：总后台；页面：骑手申请

用户端申请或骑手 APP 已实名认证的待审核骑手可修改归属。

**入口、展示与操作**

- 总后台骑手管理页签顺序：骑手管理、骑手申请、骑手资金管理、保险管理；【骑手申请】紧随【骑手管理】。
- 入口：总后台 → 小镇管理 → 骑手管理 → 骑手申请。符合改镇条件的待审核记录显示【分配小镇】，点击打开【选择小镇】弹窗。
- 弹窗默认展示全部小镇，字段为ID、小镇名称、所属区域、操作；数据量较多时分页展示。输入小镇名称可模糊查询，点击【查询】展示匹配结果；点击【重置】清空条件并恢复全部小镇。
- 每行提供【选择】。点击后弹出二次确认：“是否将骑手从【原小镇名称】更换到【目标小镇名称】？”原小镇取骑手当前归属，目标小镇取所选行。
- 点击【确认】后执行更换，成功提示“操作成功”，关闭弹窗并更新列表；点击【取消】只关闭二次确认弹窗，不修改归属。选择小镇弹窗右上角【关闭】退出本次操作。


#### 审核通过后的归属展示

所属端：总后台；页面：骑手管理

审核通过后，骑手管理显示修改后的所属小镇。

**入口、展示与操作**

- 总后台【骑手管理】列表的“所属小镇”显示修改后的新小镇；【分配小镇】沿用总后台「待审核骑手分配小镇」的选择列表及二次确认交互。


#### 未提交资质的 APP 申请注销

所属端：总后台；页面：骑手申请

总后台确认注销未提交资质的 APP 申请账号，允许重新申请。

**入口、展示与操作**

- 未提交资质的 APP 申请在操作列显示【注销】；未提交资质的骑手没有【分配小镇】操作。点击【注销】弹出二次确认：“是否注销【骑手手机号】骑手账号，注销之后骑手不可登录APP？”其中手机号完整展示，替换为当前行的实际手机号。
- 弹窗提供【确定】【取消】。点击【确定】执行注销，成功后提示“注销成功”，关闭弹窗并刷新列表；点击【取消】关闭弹窗，不注销账号，不改变本次申请。



### 测试要点

- 符合条件的待审核骑手改镇 → 查询、选择及二次确认有效，取消不修改；状态仍为待审核，两种来源审核通过后使用新归属。未提交资质账号 → 注销取消保留，确定后不可登录原账号，原手机号可重新申请。
- “骑手APP注册”“骑手APP支付宝绑定”分别核对 → 已实名认证可改镇，未提交资质可经二次确认注销，注销后原登录失效且可重新申请，处理一致。

## 骑手 APP

### 后端调整

#### 骑手 APP 账号状态与注销校验

所属端：骑手 APP；页面：注销账户

后台注销后操作提示登录过期；账号有效时注销为假的操作，仅提示。

**处理规则**

- 总后台按「未提交资质的 APP 申请注销」规则注销成功后，骑手原登录状态失效。若仍停留在 APP 原界面，点击其他操作按钮时阻止本次操作，提示“您的账号登录过期，请重新登录”。
- 账号已注销时，点击【注销账户】同样按登录失效处理，不提示小镇归属变更；刷新页面或使用原手机号重新申请，不恢复原登录状态。
- 账号仍有效、仅小镇归属变更时，操作【注销账户】，保持现有逻辑，提示：注销信息已提交，相关人员将在1~2个工作日进行处理，请勿重复提交！



### 前端 UI 调整

#### 骑手 APP 审核中页面

所属端：骑手 APP；页面：完善信息 · 审核中

申请归属调整后，保持现有审核中提示。

**入口、展示与操作**

- 骑手 APP 注册来源：后台修改申请归属后，页面保持“通过实名认证，等待审核中”的现有提示。
- 审核通过后的归属沿用总后台「待审核骑手分配小镇」规则，骑手端已有归属展示位置显示新小镇。


#### 骑手 APP 账号状态与注销校验

所属端：骑手 APP；页面：注销账户

后台注销后操作提示登录过期；账号有效时注销为假的操作，仅提示。

**入口、展示与操作**

- 骑手停留在 APP 原界面时，点击消息通知、帮助中心等其他按钮，以及【注销账户】，均按本端「骑手 APP 账号状态与注销校验」展示对应提示；账号已被总后台注销时显示登录过期提示，不展示注销成功或归属变更提示。
- 账号有效时，侧边菜单 →【注销账户】为假的操作，仅提示。



### 测试要点

- 已实名申请改镇 → 审核中提示保留，通过后展示新归属；账号有效时点击注销 → 仅显示指定提示，不执行实际注销，小镇归属变更不影响该提示。
- 总后台注销确认前或取消 → APP 原操作不受影响；确定注销后，停留原界面点击其他按钮或注销 → 提示“您的账号登录过期，请重新登录”，阻止操作；刷新或原手机号重新申请后，原登录状态仍失效。

## 运营商 PC

### 后端调整

#### 运营商审核归属校验

所属端：运营商 PC；页面：骑手审核

运营商只能审核当前仍归属本小镇的骑手。

**处理规则**

- 运营商 PC 和运营商 APP 审核骑手时，均需校验骑手当前是否仍归属本次操作的小镇；
- 如果骑手已不归属本小镇，阻止本次审核，提示“骑手小镇归属变更，请刷新后重试”，不改变骑手审核状态；
- 刷新后按当前小镇归属重新展示骑手列表；仍归属本小镇的骑手沿用原有审核规则。



### 前端 UI 调整

#### 运营商审核归属校验

所属端：运营商 PC；页面：骑手审核

运营商只能审核当前仍归属本小镇的骑手。

**入口、展示与操作**

- 入口：运营商 PC → 配送管理 → 骑手管理 → 骑手审核。归属校验失败时展示本端「运营商审核归属校验」规定的提示；刷新后，已不归属本小镇的骑手不再显示。



### 测试要点

- 骑手在审核期间移出本镇 → 通过、拒绝均被阻止并按本端规则提示，审核状态不变；刷新后移出本镇列表。
